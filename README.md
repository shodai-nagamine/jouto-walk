# 城東小あるき — PLATEAU那覇を歩く

**▶ 遊ぶ: <https://shodai-nagamine.github.io/jouto-walk/>**（スマホ可）

<img src="jouto-walk-qr.png" width="180" alt="公開URLのQRコード">


那覇市 **城東小学校** を中心とした 1km 四方を、国土交通省 PLATEAU の実測データ
（建物 CityGML LOD1 ＋ 地形 DEM）から起こして歩き回れるようにした Three.js の一人称ゲーム。
街に散らばった **10体のシーサー** を探して保護するのが目的。

- 建物 **1,905棟**（実在の footprint と高さ）
- 地形 **201×201 の 5m 格子**（標高 84.8〜154.0m の起伏をそのまま再現）
- 城東小の地表標高 115m。首里寄りの高台という土地の性格が歩くと分かる

## 起動

ローカルで動かす場合:

```bash
python3 -m http.server 8945 --directory ~/dev/apps/jouto-walk/public
```

<http://localhost:8945> を開く。ビルド不要（Three.js は `public/lib/` に同梱）。

## 公開

`main` に push すると GitHub Actions（`.github/workflows/pages.yml`）が
`public/` を GitHub Pages へ配信する。ビルド手順は無く、成果物をそのまま上げるだけ。
配信サイズは約 1.3MB（`world.json` は gzip で 0.2MB）。

### デプロイでハマった点（2026-08-06）

- `concurrency` は **`cancel-in-progress: false`**。`true` だと進行中のデプロイを
  打ち切って Pages 側が `Deployment cancelled` になり、上げ直しても反映されない
- **失敗したジョブを `gh run rerun --failed` で再実行しない**。同じ run に
  `github-pages` という名前のアーティファクトが2つでき、
  `Multiple artifacts named "github-pages"` で必ず落ちる。新しい run を投げること
  （`gh workflow run pages.yml` か、新規 push）
- `deploy-pages` の `timeout` は **10分が上限**（それ以上を書いても丸められる）。
  Pages 側の配信がこれを超えると **ジョブは failure になるが、配信は後から完了して
  公開される**。赤いバツを見たら、まず本番の中身を確認する:

  ```bash
  curl -s https://shodai-nagamine.github.io/jouto-walk/main.js | grep -c setFly
  ```

## 操作

PC:

| キー | 動作 |
| --- | --- |
| `W` `A` `S` `D` | 移動 |
| `Shift` | 走る |
| `Space` | ジャンプ／**長押しで飛行モード** |
| `Space` / `Shift`（飛行中） | 上昇／下降 |
| マウス | 見回す（ポインタロックが効かない環境では左ドラッグ） |
| `Esc` | ポーズ |

スマホ・タブレット:

- **画面の左半分**を押すとそこがスティックの中心になり、倒した方向へ歩く。
  倒した量が速度で、目一杯倒すと走る
- **画面の右半分**をなぞると見回す。移動と同時に操作できる（指ごとに追跡している）
- 右下の**ジャンプ**（**長押しで飛行モード**、飛行中は押しっぱなしで上昇＋
  左どなりに「おりる」ボタンが出る）、左上の**⏸**（ポーズ）
- 右下の**地図をタップ**すると全画面に拡大（もう一度タップで戻る）

シーサーは**光の柱**で遠くからでも分かる。4m まで近づくと自動で保護。

`?touch=1` を付けると PC でもタッチ UI を確認できる（`?touch=0` で強制的に PC 操作）。

## ワールドデータの作り直し

`public/data/world.json` は下のコマンドで生成する。CityGML と DEM の原本、および
パーサ資産（`gml_to_schematic.py` / `dem_grid.py`）は `~/dev/tools/blender-mcp/data/naha/` にある。

```bash
~/dev/tools/blender-mcp/.venv/bin/python tools/build_world.py \
  --center 26.2233 127.7322 --size 1000 \
  --gml 39272568.gml 39272578.gml \
  --dem 392725_dem_55.gml \
  --tran 39272568_tran.gml 39272578_tran.gml \
  --rail naha_railway.geojson --stations naha_station.czml \
  --bus naha_bus_osm.json --osm-named naha_named_osm.json \
  --bus-routes naha_busroutes_osm.json --signals naha_signals_osm.json \
  --footways naha_footways_osm.json \
  --out public/data/world.json
```

バス停と地名辞書は OpenStreetMap から Overpass API で取る（クエリは
`naha_bus_osm.query.txt` / `naha_named_osm.query.txt` に保存してある）:

```bash
curl -s -X POST -d @naha_bus_osm.query.txt https://overpass-api.de/api/interpreter -o naha_bus_osm.json
```

タイトル画面の「開発ログ」は git 履歴から作る。手書きの記録ではないので
書き忘れも盛りもない。GitHub Actions が push のたびに作り直すため、
ワークフローの checkout は `fetch-depth: 0`（全履歴）にしてある:

```bash
python3 tools/build_changelog.py --out public/data/changelog.json
```

市議会の言及は world.json を作ったあとに別途生成する（Postgres が要る）:

```bash
python3 tools/link_council.py --world public/data/world.json --out public/data/council.json
```

### 市議会リンクの作り方

1. **地名辞書**: CityGML の `gml:name` はタイルあたり 4〜7 件しかないので、
   OSM の名前付き地物（`--osm-named`、196 件）で厚くする。これで
   「石嶺市営住宅」「石嶺公民館」「市道城東城北線」など議事録に出る名前が入る
2. **絞り込み**: 議会が議題にするのは公共施設と道路なので、OSM のタグか
   名前のキーワードで**公共施設だけに限る**。これをやらないと
   「ほっともっと」が金芽米の話に、「コープ」が労働者協同組合ワーカーズコープに
   当たるといった誤検出が出る（実際に出た）
3. **並び順**: 発言者不明（32 件ある）と議長の議事進行を後ろへ回し、
   議員の質疑と執行部の答弁を先に出す

現在は **4 地点 / 8 発言**（城東小学校・石嶺中学校・石嶺公民館・石嶺市営住宅）。
収録が那覇市議会の令和 8 年 2 月定例会 13 日分なので、会議録を増やせばそのまま増える。

- `--center` は緯度経度。別の場所にすれば那覇市内のどこでも作れる（該当メッシュの GML が要る）
- 城東小 26.2233,127.7322 は 3次メッシュ `39272568`。1km 四方だと北隣の `39272578` も必要
- DEM は `_55` 象限のみが該当（`_50` は範囲外で 0 点になる）
- `--tran` は交通（道路）モデル。省略しても動くが、道路は密度場からの推定のみになる
- `--rail` / `--stations` はゆいレール。CityGML ではなく GeoJSON と CZML（PLATEAU の
  RELATED データセット `d_47201_railway` / `d_47201_station`）を使う

## タイル化（モノレール沿いへの拡張、進行中）

世界をモノレール沿いに広げるため、**1km 格子のタイル**に分ける。四角く広げると
地面テクスチャが破綻する（0.5m/px のまま 3km 四方にすると 6144px＝3,770 万ピクセルを
素の JS ループで焼くことになる）が、**タイルごとに今と同じ 1km 世界を作れば
既存のパイプラインがそのまま使える**。

- `--origin LAT LON` で**全タイル共通の原点**を指定する。緯度経度→メートルの換算を
  原点の緯度で統一しないと、タイルごとに縮尺がずれて継ぎ目が出る
- 各タイルの `meta.offset` に、原点から見た中心位置（m）が入る
- OSM は**タイルをまとめて覆う 1 回のクエリ**で取り、同じファイルを
  `--bus` `--osm-named` `--signals` `--footways` に渡す。
  各パーサはタグを見て自分の担当だけを拾う（この絞りが無いと
  「市道○○線」が歩道として描かれる）

生成済み: `t_0_0`（城東小・建物 1,905）／ `t_-1_0`（首里・建物 2,431・儀保/首里の 2 駅）。
全線（那覇空港〜石嶺 16 駅）を路線±600m で覆うと **41 タイル・約 29MB**。

### 残っている設計判断

線路・バス路線・駅は**タイルをまたぐ**ので、タイルに入れず
**corridor.json（路線全体で 1 つ）**に分ける予定。こうしないと
どのタイルが読み込まれているかで列車の経路が変わってしまう。

## 実装のポイント

- **建物**: 全 1,905 棟を 1 つの BufferGeometry に詰めてドローコール 1 回。壁と屋根を
  `addGroup` で 2 マテリアルに分け、壁だけ procedural な窓テクスチャを貼る。UV の横は
  外周の累積距離、縦はその建物の地面からの高さなので、棟をまたいでも階が揃う
- **道路**: PLATEAU 交通モデル（tran LOD1）の道路「面」894 枚。中心線ではなく実際の
  路面形状が入っている（高さは一律 0 なので平面として扱い、地面テクスチャに焼く）。
  1.8m ぼかした版を路肩の帯に使う
- **地面**: 上の道路を最優先で塗り、それ以外は建物 footprint を太らせた「敷地」と、
  14m ぼかした密度場から 敷地／路肩／緑地 を連続補間で塗り分ける。tran に入らない
  私道・路地は密度から弱く（係数 0.5）推定して補う。2048px（0.5m/px）なので足元用に
  細かいノイズを `onBeforeCompile` で乗算している
- **モノレール**: 沖縄都市モノレール（ゆいレール）。線形は **1本 1,025m**。
  元データは路線が細切れの feature で入っているので、**先に端点で繋いでから**
  ワールドで切る（繋がないと 813m/82m/130m の断片になり、列車が短い往復をする）。
  線形データは国土数値情報由来の
  **2D 中心線で高さを持たない**ので、跨座式の高架らしく「地形＋10.5m」を移動平均で
  ならして桁を通し、26m ごとに橋脚を降ろしている（橋脚は InstancedMesh で 1 ドローコール）。
  桁は角断面のリボンとして自前で張る。車両 2 両が線形を往復する（端で消えないように
  ワープではなく折り返し）
- **駅とホーム**: 石嶺駅がワールド内（中心から南西 約 510m）。**ホーム床は桁の高さから
  自動で決まる**（桁中心 −0.7m ＝ 車両の床。実測で地上 106.3m に対し床 114.9m）。
  地上から 19 段の階段で上がれる。
  - PLATEAU の駅舎（17×53m・天端 120.6m）は**中身のない箱**なので、そのままだと
    ホームと階段が壁の中に閉じ込められて一歩も動けない。**駅を含む建物は描画にも
    当たり判定にも入れず**、自前のホーム・上屋・階段で置き換えている
  - 階段が昇れるのは `blocked()` に **STEP（0.55m）の段差許容**を入れたから。
    ホームも階段も `addSolid()` で建物と同じ footprint＋天端として登録するだけでよい
  - 列車が走る線形は**駅のある線形**を選ぶ。長さで選ぶと駅が別の線形に乗っていて
    永久に停まらないことがある（実際に踏んだ）
- **市議会の言及**: `tools/link_council.py` が
  [okinawa-civic-api](https://github.com/shodai-nagamine) の Postgres（那覇市議会
  会議録 9,749 発言）を、ワールド内の施設名で全文検索して地点に結びつける。
  16m 以内に近づくとパネルが出て、**発言者・日付・抜粋・原文リンク**が読める
  （同じ地点に複数あるときは `Q` かパネルのタップで送る）
- **モノレールに乗れる**: 石嶺駅で列車は 9 秒停まる。ホーム上で列車に近づくと乗れる。
  **高さも判定に入れている**ので、高架の下の地上からは乗り込めない。
  降りるとホーム側に降ろされる
- **バスに乗れる**: バス停に停まっているバスへ 6.5m 以内に近づくと乗れる（`E` かボタン）。
  乗車中は移動入力を切って座席（左の窓側、床から 2.15m）へ貼り付け、**見回しだけ自由**。
  バスの更新はプレイヤーより**先**に回す（後だと 1 フレーム遅れて座席がずれる）。
  そばに人が居るバス停では停車時間を 2.2 秒 → 7 秒に延ばして乗る余裕をつくる。
  降車は進行方向の右側（歩道側）に降ろし、塞がっていたら候補を順に試す
- **走るバス**: 経路は OSM のバス路線リレーション（**那覇バスの実系統**）。
  この 1km 四方には 23 系統が通っていて、そのうち世界内を長く走る 4 本
  （94 首里駅琉大快速線 / 346 那覇西原線 / 19 首里駅循環線 / 8 首里城下町線）を採用。
  リレーションのメンバー way は向きが揃っていないので端点の近さで反転させながら繋ぎ、
  ワールドで切って**いちばん長く連続する区間**だけを使う。
  経路上でバス停に近づく地点を先に拾っておき、そこで 2.2 秒停まる。
  **時刻表は持っていないので発車タイミングは任意**（GTFS が手に入れば差し替えられる）
- **信号**: OSM の信号ノード **55 基**（車両用 26／歩行者用 29）を、**交差点 11 箇所**に
  束ねてある。交差点の中心から見た向きで東西（axis 0）と南北（axis 1）に振り分け、
  直交する系統が交互に青になる（同時に青にならないことと、全赤の間があることを検証済み）。
  交差点ごとに位相をずらしてあるので街全体が一斉には変わらない。
  灯火は 165 個を 1 つの InstancedMesh に入れて **per-instance color を書き換えるだけ**
  （0.15 秒ごと）。並びは**運転者から見て左から青・黄・赤**（日本の並び。灯器は
  交差点の中心を向いているので、その視点がそのまま運転者の視点になる）。
  歩行者用は上が赤、下が青
- **バスは赤で止まる**: 各路線の経路上で信号に差しかかる地点を先に拾い、進行方向から
  見る系統（東西か南北か）も決めておく。停止線の 3.5m 手前で青以外なら進まない
- **歩道と車道の区別**: PLATEAU の交通モデルは那覇では **LOD1 のみ**で
  `TrafficArea` / `AuxiliaryTrafficArea` を持たない = **歩道と車道の区別が無い**
  （手元の tran GML を grep して 0 件を確認）。そこで歩行者系は OSM から取る。
  歩道 166・横断歩道 50・階段 27・小径 18。歩道は 2.6m 幅の明るい舗装として
  車道の上に描き、**横断歩道は白い縞**として最後に重ねる（縞は歩行者の進む向きと
  平行な帯なので、way に沿う線を左右にずらして引く）。
  路面を横断方向にサンプルすると明暗が 6 回切り替わることを確認済み
- **店舗**: OSM の名前付き地物から店舗系 39 件を拾い、**食／買／医／金／学**の
  5 分類に色分けした看板を出す（営業時間があれば併記）。表示は **62m 以内だけ**
- **歩行者**: 取り込んだ歩道網（126 本）の上を **36 人**が歩く。時速 3.6〜5.4km。
  数は**固定**で、165m より遠ざかった人はプレイヤーの手前（30〜130m）へ湧かし直す。
  こうしておくと**世界を広げても人の処理コストが変わらない**。
  胴と頭をそれぞれ 1 つの InstancedMesh にまとめ、per-instance color で
  服と肌の色を振っているので描画は 2 回
- **バス停**: 20 基（うち「城東小学校前」は校門のすぐ前）。支柱と台座は InstancedMesh、
  標識は canvas テクスチャのスプライトにして向きを持たせない。名札が 20 枚も常時
  見えると画面が埋まるので、**135m 以内だけ表示**する
- **シーサーの配置**: 道路面の重心を候補にし、互いに 110m 以上離して 10 体選ぶ
  （足りなければ 70m → 40m と間隔を緩める）。道沿いに立つので必ず辿り着ける
- **屋根**: 低層の一部を赤瓦色にすると俯瞰したとき一気に沖縄になる
- **当たり判定**: footprint を 24m の空間ハッシュに登録し、近傍セルだけ点-多角形＋
  線分距離で判定。移動は軸ごとに試すので壁ずりが効く。**足元の高さ `y` を渡すと
  建物の天端より上は素通りできる**ので、飛行で屋根を越えられる
- **接地面**: `supportY()` が地表と建物の天端の高い方を返すので、**屋根の上に立てる**
  （縁から出れば落ちる）
- **飛行**: マイクラのクリエイティブ準拠。ジャンプ長押し 320ms で切り替え、
  押している間に1回だけ発火させる（押しっぱなしでも連続トグルしない）。
  重力を切って `vy` を直接指定するので、指を離すとその高度でホバーする
- **地表高さ**: 5m 格子を双一次補間

## スマホ対応

端末の素性は事前に分からないので、**判定できるものは分岐し、分からないものは実測して落とす**方針。

- **端末判定**（`pointer: coarse` か `maxTouchPoints`）で、解像度上限 1.5、影 1024px、
  アンチエイリアス off、地面テクスチャ 1024px（2048px だと 4M ピクセルの JS ループが重い）
- **実測 fps が 40 を切ったら段階的に降格**（影 512px → 解像度等倍 → 影を切る）。
  影を切るときはシェーダを組み直す必要があるので、全マテリアルに `needsUpdate` を通知する。
  `dbg.degrade()` で手動発火できる
- **縦持ちは画角を 72° → 88°** に広げる。Three.js の fov は垂直方向なので、
  そのままだと縦長画面で水平の視野が極端に狭くなる
- 初期の向きは**最も遠くまで開けている方位**（＝街路）を向く。壁を向いて始まると何も見えないため
- `touch-action:none` ＋ `preventDefault` でスワイプによるスクロールと二本指ズームを止め、
  `env(safe-area-inset-*)` でノッチを避ける。開始時に全画面化を試みる（非対応端末では無視される）
- 画面が隠れたら自動ポーズ（着信・ホームに戻ったときに走りっぱなしにしない）

## 出典・ライセンス

**建物・地形データ**: [国土交通省 PLATEAU](https://www.mlit.go.jp/plateau/)（CityGML, EPSG:6697）を
**加工して作成**。PLATEAU のデータは「公共データ利用規約（第1.0版）」（PDL1.0）に準拠し、
CC BY 4.0 と互換。再配布・商用利用とも可能だが、次の3点が条件になる。

1. 出典を明記する（例:「出典：国土交通省 PLATEAUウェブサイト」）
2. 加工した場合はその旨を出典とは別に明記する（例:「…を加工して作成」）
3. 国土交通省が作成したかのような態様で公表しない

このリポジトリでは `public/data/world.json` が加工済みの再配布データにあたるため、
タイトル画面に上記3点を常時表示している（`index.html` の `#card .credit`）。
公開先を変えたり UI を作り替えるときも、この表示は落とさないこと。

**バス停**: [OpenStreetMap](https://www.openstreetmap.org/copyright) contributors
（**ODbL 1.0**）を加工して作成。Overpass API で取得。

> ⚠️ バス停に国土数値情報（P11 バス停留所）を使ってはいけない。
> P11 は「**非商用**」区分で、[利用規約](https://nlftp.mlit.go.jp/ksj/other/agreement_02.html)に
> 「非商用目的のみでの利用（**ただし複製物の再配布を除く**）」と明記されている。
> `world.json` に座標を載せて公開するのは複製物の再配布にあたるため、
> 公開物には使えない。ODbL の OSM ならクレジットと継承を守れば再配布できる。
> なお ODbL は派生データベースに継承を要求するので、`world.json` のバス停部分は
> ODbL 扱いになる。
